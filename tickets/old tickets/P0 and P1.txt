# Asteroid Colony Prototype

## Phase 0 + Phase 1 Execution Specification

**Engine:** Unity 6000.5.9f1
**Project preset:** HD URP
**Goal:** Establish the smallest causal colony simulation: eight colonists consume food, two farmers physically commute to a farm, the farm produces food, and a shuttle physically transports that food back to the Command Post.

This is a prototype. Do not build generalized systems merely because they may be useful later.

# 2. Intentional Prototype Simplifications

These decisions are deliberate.

### Food consumption

All eight Command Post residents consume food from the Command Post inventory regardless of their current physical location.

This is temporary.

Do **not** create personal inventories, packed lunches, meal logistics, or food consumption aboard the shuttle yet.

The purpose of food in Phase 1 is to create a demand that must be replenished through physical freight transport.

### Pilots

Two colonists have the `ShuttlePilot` role.

Only **Pilot 1** is assigned to the shuttle during Phase 1.

Pilot 1 remains with the shuttle.

Pilot 2 currently does nothing except consume food.

Do not implement pilot shifts yet.

A shuttle with no assigned pilot is unavailable for contracts.

### Farmers

The two farmers share the same simple shift cycle.

They physically travel:

```text
Command Post
→ Farm
→ Command Post
```

They produce food only while physically present at the Farm and in their working phase.

### Shuttle movement

Movement is direct transform movement between locations.

No physics.

No pathfinding.

No docking.

The shuttle may remain wherever its previous contract ended.

When assigned another contract elsewhere, it may travel empty to the pickup location.

# P0-T01 — Simulation Clock and Event Log

## Create

```text
Core/SimulationManager.cs
Core/SimulationLog.cs
```

## SimulationManager responsibilities

`SimulationManager` is a MonoBehaviour attached to `Managers`.

Expose in the Inspector:

```text
Paused
Speed Multiplier
Game Hours Per Real Second
Tick Interval Seconds

Current Game Hour
Current Tick
```

Recommended defaults:

```text
Paused = false
Speed Multiplier = 1
Game Hours Per Real Second = 1
Tick Interval Seconds = 0.1
```

Therefore approximately:

```text
1 real second = 1 game hour
```

Implement a central simulation tick.

Define:

```csharp
public interface ISimulationTickable
{
    void SimulationTick(float deltaGameHours);
}
```

`SimulationManager` maintains registered tickables.

Do not search the scene every tick.

Objects register once and are subsequently ticked by the manager.

Expose methods equivalent to:

```csharp
Register(ISimulationTickable tickable)
Unregister(ISimulationTickable tickable)
```

The simulation manager advances game time and invokes registered tickables.

## SimulationLog responsibilities

Attach `SimulationLog` to `Managers`.

Maintain an Inspector-visible rolling list of recent simulation messages.

Recommended capacity:

```text
100 entries
```

Each event should contain game time:

```text
[03.40h] Shuttle 1 assigned Contract #4
```

Also send the same message to `Debug.Log`.

Provide a simple public/static logging entry point appropriate for this prototype.

Do not create a generalized telemetry framework.

## Acceptance

Entering Play mode:

* simulation time advances;
* pausing stops simulation time;
* changing speed multiplier affects simulation speed;
* tick counter advances;
* event log is visible in Inspector;
* no scene searches occur every tick;
* no errors appear in Console.

## InventoryComponent

Attach this to:

```text
Command Post
Farm
Shuttle
```

Use serializable inventory entries.

Each entry must expose:

```text
Resource
On Hand
Reserved
Available
Capacity
```

Where:

```text
Available = On Hand - Reserved
```

Implement operations sufficient for Phase 1:

```text
Add
Remove
Reserve
ReleaseReservation
WithdrawReserved
```

Required invariants:

```text
On Hand >= 0
Reserved >= 0
Reserved <= On Hand
On Hand <= Capacity
```

No resource may be created or destroyed during transfer except through explicit production or consumption.

The Inspector must visibly show current inventory state during Play mode.

## Acceptance

```text

On Hand: 20

Available: 12
Capacity: 40
```

---

## Freight contract data

Add:

```text
Resource Type
Quantity
Source Inventory
Destination Inventory
```

For Phase 1 the resource is always Food.

Creating a freight contract reserves the requested quantity at the source inventory.

If only part of the requested amount is available, it is acceptable to create a contract for the available amount.

If zero is available, do not create an empty contract.

Only one active Command-Post food-resupply contract should exist at a time.

---

## Passenger contract data

Contain a list of `ColonistAgent` passengers.

Passenger contracts require those colonists to currently be at the source location when created.

For Phase 1, both farmers may travel together on one contract.

---

Attach to `Managers`.

Responsibilities:

```text
Generate unique contract IDs
Own all active/history contracts
Create freight contracts
Create passenger contracts
Expose open contracts
Mark contracts assigned/completed/cancelled
Query whether matching active contracts already exist
```

Keep completed contracts visible in an Inspector list/history for debugging.

Do not delete them immediately.

## Acceptance

From code, creating a freight contract visibly:

* adds a contract to ContractManager;
* changes food from Available to Reserved at the Farm;

## LogisticsManager

Attach to `Managers`.

On simulation ticks:

1. Find an idle available shuttle.
2. Find the highest-priority compatible open contract.
3. Assign that contract.
4. Tell the shuttle to execute it.

One shuttle exists, so do not build fleet optimization.

Use simple priority followed by creation order.

Suggested priorities:

```text
Passenger commute = 100
Food resupply      = 50
```

---

## Contract execution

A shuttle executes:

```text
Current position
    ↓
Travel empty to source if necessary
    ↓
Pickup/load
    ↓
Travel to destination
    ↓
Unload
    ↓
Contract complete
    ↓
Shuttle becomes idle at destination
```

### Movement

Use direct transform movement.

No physics.

Movement should respond to simulation time/speed.

### Freight loading

At pickup:

```text
Farm:
    reserved stock is withdrawn

Shuttle:
    cargo inventory receives it
```

At this point the food is physically owned by the Shuttle inventory.

### Freight unloading

At destination:

```text
Shuttle:
    cargo decreases

Command Post:
    food increases
```

Only after unloading does the Command Post own the food.

### Passenger loading

At pickup:

```text
Colonist.CurrentLocation = Shuttle
Activity = Passenger
```

Move/parent the capsule to the Shuttle anchor.

### Passenger unloading

At destination:

```text
Colonist.CurrentLocation = Destination
```

Move/parent the capsule there.

The shuttle pilot remains aboard.

---

## Logging

```text
Contract #1 assigned to Shuttle 1
Shuttle 1 traveling to Farm 1
Farmer 1 boarded Shuttle 1
Farmer 2 boarded Shuttle 1
Shuttle 1 departed Farm 1
Shuttle 1 arrived Command Post
Contract #1 completed
```

Do not log every movement tick.

```text

```

---

## Consumption rule

Every simulation tick:

```text
resident count
× consumption rate
× delta game hours
```

is removed from Command Post food.

For Phase 1, all eight residents count even when temporarily away.

This simplification must be commented in code so nobody later mistakes it for the intended final design.

---

## Shortage

If consumption requires more food than exists:

```text
Food inventory reaches 0
FoodShortageActive = true
```

Log the shortage.

Do not kill colonists.

Do not create health consequences.

When food becomes available again:

```text
FoodShortageActive = false
```

Log recovery.

---

## Resupply demand

When:

```text
Food On Hand < Reorder Threshold
```

and there is no existing active incoming Food contract:

```text
Desired =
Target Food Stock - current food
```

Limit by:

```text
Maximum Order Size
Farm available unreserved food
```

If the result is greater than zero, create:

```text
Freight Contract
Farm 1 → Command Post
Resource = Food
```

The Farm food becomes reserved immediately.

The Command Post receives nothing until the Shuttle actually unloads.

# 5. Phase 1 Completion Definition

Phase 1 is complete when the following closed loop can continue indefinitely without manual intervention:

```text
Farmers wake/rest complete
        ↓
transport requested
        ↓
shuttle carries farmers to Farm
        ↓
farm produces Food
        ↓
Command Post consumes Food
        ↓
Command Post requests resupply
        ↓
Farm Food reserved
        ↓
shuttle picks up Food
        ↓
Food exists aboard shuttle
        ↓
shuttle physically returns
        ↓
Command Post receives Food
        ↓
farmers finish work
        ↓
transport home requested
        ↓
farmers return
        ↓
farmers rest
        ↓
cycle repeats
```

The simulation must also fail causally when the shuttle is disabled.

That is the complete Phase 0/1 prototype.

Do not proceed to construction, additional buildings, new resources, richer crew management, or presentation polish until this loop behaves correctly and is understandable through the Inspector.
